# WEB-040 · 构建、更新和下载

`site-build` 用公开 `qunxing-data` 和本仓库已有生成器构建完整静态站。输出题库、静态 API、llms-full.txt、sitemap.xml、下载页和版本数据。PR 只产出预览工件。主分支成功构建后只更新 `site-artifacts` 分支。

服务器保持拉取式。合并后先确认 `site-artifacts` 首个工件和线上检查都通过，再把 `qunxing-www-deploy.service` 的 `BRANCH` 切到 `site-artifacts`。回滚恢复对 `main` 的拉取。未用 GitHub Pages 作为生产依赖。

## 首个桌面 Release

发布必须附 `Qunxing-Setup.exe`、`Qunxing-Windows-x64.zip`、`SHA256SUMS.txt`。构建读取 GitHub 发布的版本、日期、文件大小及校验和；无 Release 时沿用未发布页面。真实签名状态需另由发布流程证实。

在目标服务器执行 `python3 deploy/bin/release_assets.py /srv/qunxing/downloads`。下载到未对外的同盘暂存目录。两个文件的大小和 SHA-256 一致后，整目录切换为版本路径。验收后在 www HTTPS 的 server 内加入 `qunxing-download-files.inc`，校验重载。构建读到公网镜像相同的 `SHA256SUMS.txt` 才显示镜像入口。文件仍由当前美国 VPS 提供。

## 离线签名

根身份通过 minisign 签发 `keys.json`，内容有 `epoch` 和 `keys[]`。每个在线签名公钥条目含 `id`、`public_key`、`expires_at`，授权 90 天。根公钥通过客户端发放。

准备策略 JSON，字段为 `epoch`、`version`、`key_id`、`min_app_version`、`mirrors[]`、`inbox_endpoints[]` 和 `packages`（名称到相对文件路径的映射）。将实际题库、价格和查新来源文件列为更新包。收件关闭时保持 `inbox_endpoints` 为空。只添加经过验收的镜像。

在离线环境调用 `build_manifest.py`，参数为 `--policy`、`--keys`、`--root-public`、`--signing-identity`、`--assets`、`--output`。已有发布时用 `--previous` 校验升级。程序先校验根签名，再计算文件哈希并用更新公钥验证生成的签名。密钥文件放在产物目录之外。使用输出目录的 JSON 和签名上线，记录版本和摘要。正式发布仍需已确认的根公钥、同版价格及查新来源数据。

## 检查

`python3 -B deploy/bin/test_site_build.py -v` 验证缺少 Release、校验失败留在暂存、更新包摘要、过期约束及 sitemap 和文本生成。网站内容维护仍用现有 `public/` 与 `tools/` 工作流。
